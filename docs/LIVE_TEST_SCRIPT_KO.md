# EMS Relay 통합 테스트·시연 대본

## 1. 권장 실행 방식

- 전체 흐름 시연: `https://main.d2edch3bt6kxej.amplifyapp.com/demo/workflow`
- 실제 연동 검증: 구급대원 `/paramedic`, 상황실 `/control`, 병원 `/hospital`, 보고서 `/reports`
- 발표 전 첫 실행은 **전체 흐름 시연**으로 진행한다. 이 경로는 한 브라우저에서 역할을 바꾸며 동일 사건을 끝까지 보여주기 가장 안정적이다.
- 실제 연동 검증은 서로 다른 브라우저 프로필 또는 시크릿 창 3개에서 역할별 Cognito 계정으로 로그인해 진행한다.

## 3. 발표자 도입 멘트

> EMS Relay는 AI가 병원이나 진단을 결정하는 시스템이 아닙니다. 구급대원이 확인한 환자정보를 음성에서 구조화하고, 사람이 검토한 값만 공통 사건 기록에 반영해 구급대·상황실·병원이 같은 정보를 보도록 연결합니다. 지금부터 119 출동 배정 이후 현장평가, 수용 문의, 이송, 인계, 보고서 검토까지 한 사건으로 보여드리겠습니다.

## 4. 전체 흐름 시연 대본

### 장면 1. 출동과 현장 도착

1. 상단 `초기화`를 누르고 `구급대` 화면을 연다.
2. 사건 카드 `EMS-GW-050`을 선택한다.
3. `출동 시작` → `현장 도착` → `환자 접촉`을 순서대로 누른다.

발표 멘트:

> 신고 단계에서는 환자를 직접 확인하지 않았으므로 연령대와 신고 증상만 표시합니다. 출동·현장 도착·환자 접촉 시각은 구급대원의 업무 버튼을 기준으로 자동 기록됩니다.

확인 사항:

- 버튼을 누른 시각이 사건 타임라인에 추가된다.
- 신고 내용은 현장 확인값과 구분되어 표시된다.

### 장면 2. 활력징후와 의식 수준 입력

1. `활력징후 입력 시작`을 누른다.
2. 아래 값을 직접 입력한다.
   - 혈압 BP: `163/90`
   - 맥박 PR: `91`
   - 호흡수 RR: `23`
   - SpO₂: `96`
   - 체온: `37.4`
   - 혈당: `116`
3. AVPU에서 `A`를 선택한다.

발표 멘트:

> 장비 자동 연동을 전제로 하지 않습니다. MVP에서는 구급대원이 측정한 값을 직접 입력하고, 음성 입력도 함께 사용할 수 있습니다. 수치와 단위는 구급 현장에서 사용하는 형식으로 표시합니다.

### 장면 3. PTT 음성 입력과 HITL 확인

각 차수마다 `누르고 말하기`를 누른 채 대사를 읽고, 말을 마치면 손을 뗀다. 변경안 화면에서는 **실제로 확인한 항목만 선택**한 뒤 `선택 항목 반영`을 누른다.

#### 1차 — 최초 환자 상태

구급대원 대사:

> 73세 여성 환자입니다. 주호소는 쥐어짜는 양상의 흉통입니다. 현재 의식은 AVPU A입니다.

기대 항목:

- 연령: 73세
- 성별: 여성
- 주호소: 쥐어짜는 양상의 흉통
- AVPU: A

#### 2차 — 발생시각과 병력

구급대원 대사:

> 증상 발생 시각은 9시 38분이며 환자와 목격자에게 확인했습니다. 과거력은 당뇨와 심부전입니다. 와파린을 복용한다고 진술했습니다. 약물 알레르기는 확인하지 못했습니다.

기대 항목:

- 발생시각: 09:38, 확인된 시각
- 과거력: 당뇨, 심부전
- 복용약: 와파린, 진술 기반
- 약물 알레르기: 미상

#### 3차 — 활력징후와 처치

구급대원 대사:

> 최초 활력징후는 혈압 163에 90, 맥박 분당 91회, 호흡수 분당 23회, 산소포화도 96퍼센트, 체온 37.4도, 혈당 116입니다. 심전도 감시와 12유도 심전도, 정맥로 확보를 시행했습니다. 12유도 심전도 상세 소견은 아직 확인하지 못했습니다.

기대 항목:

- BP 163/90 mmHg
- PR 91회/분
- RR 23회/분
- SpO₂ 96%
- BT 37.4℃
- BST 116 mg/dL
- 처치: 심전도 감시, 12유도 심전도, 정맥로 확보
- 12유도 심전도 상세 소견: 미상

HITL 검증 규칙:

- 음성에 없던 값이 제안되면 선택하지 않는다.
- 숫자나 단위가 다르면 선택하지 않고 다시 말하거나 직접 입력한다.
- `와파린`은 확인약이 아니라 **환자 진술 기반**으로 남긴다.
- `약물 알레르기`와 `심전도 상세 소견`은 임의로 채우지 않고 **미상**으로 남긴다.
- 병원 전 판단은 확정 진단으로 바꾸지 않는다.

### 장면 4. 환자 확인본과 병원 후보

1. `환자 확인본 만들기`를 누른다.
2. 요약 화면에서 `병원 후보 확인`을 누른다.

발표 멘트:

> Agent가 만든 것은 자동 확정 기록이 아니라 변경안입니다. 구급대원이 선택한 항목만 확인본에 들어갑니다. 병원 후보는 거리·ETA와 기관 정보를 탐색 범위로 제공할 뿐, AI가 이송병원을 결정하지 않습니다.

### 장면 5. 상황실의 최소 개입

1. 필요하면 구급대 화면에서 `상황실 연락 지원 요청`을 누른다.
2. 상단 `상황실`로 이동한다.
3. `구급대 연락 지원`을 누르고 다시 `구급대`로 돌아온다.

발표 멘트:

> 상황실은 환자 평가를 다시 입력하거나 병원을 대신 결정하지 않습니다. 문의 진행상태를 공유하고 연락이 막힌 경우만 지원합니다.

### 장면 6. 첫 병원 문의와 추가정보 요청

1. 구급대 화면에서 `해솔응급의료센터`의 `이 병원에 수용 문의`를 누른다.
2. 상단 `병원`으로 이동한다.
3. `추가정보 요청`을 누른다.
4. `재평가 활력징후`, `항혈소판제·항응고제 복용`을 선택하고 `선택 항목 요청`을 누른다.
5. 다시 `구급대` → 병원 탭으로 이동한다.
6. `확인값·미상 구분해 회신`을 누른다.

발표 멘트:

> 병원은 전체 자유문을 반복해서 요구하는 대신, 현재 수용 판단에 필요한 항목만 선택합니다. 구급대는 확인값과 미상을 구분해 회신하며, 세 화면에 동일한 상태가 동기화됩니다.

### 장면 7. 수용 곤란과 다음 병원 문의

1. `병원` 화면에서 `수용 곤란`을 누른다.
2. 사유 `관련 진료과 대응 곤란`을 선택한다.
3. `수용 곤란 회신`을 누른다.
4. `구급대`로 돌아간다.
5. 두 번째 후보 `푸른강권역응급센터`에서 `이 병원에 수용 문의`를 누른다.
6. `병원` 화면에서 `수용 가능` → `수용 가능 회신`을 누른다.
7. `구급대` 화면에서 `이송병원으로 확정` → `이송 시작`을 누른다.

발표 멘트:

> 수용 곤란은 실패로 지우지 않고 사유와 시각을 남깁니다. 다음 후보를 다시 검토하고, 최종 이송지는 구급대원이 병원 회신을 확인한 뒤 확정합니다.

### 장면 8. 이송 중 재평가

1. `재평가 누르고 말하기`를 누른 채 아래 문장을 말한다.

구급대원 대사:

> 재평가합니다. 흉통과 식은땀이 일부 호전됐습니다. 의식은 AVPU A입니다. 혈압 148에 86, 맥박 분당 88회, 호흡수 분당 21회, 산소포화도 100퍼센트, 체온 37.4도, 혈당 116입니다. 급성관상동맥증후군 의심은 병원 전 평가이며 확정 진단은 아닙니다.

2. 재평가 경로와 값이 맞는 항목만 선택해 `선택 항목 반영`을 누른다.
3. 음성 입력이 원활하지 않으면 `측정값 직접 입력`을 열어 동일 값을 입력하고 `측정시각과 함께 저장`을 누른다.

중요 확인:

- 재평가값은 최초 활력징후를 덮어쓰지 않고 별도 재평가 항목에 저장되어야 한다.
- `급성관상동맥증후군 의심`은 확정 진단이 아니라 병원 전 판단으로 표시되어야 한다.

### 장면 9. 병원 도착과 인계

1. 구급대 화면에서 `병원 도착`을 누른다.
2. 인계 탭에서 `구두·전자 인계 완료`를 누른다.
3. `병원` 화면으로 이동한다.
4. 인수자 성명과 직종을 확인하고 `환자 인수 확인`을 누른다.

발표 멘트:

> 구급대원의 인계 전송만으로 사건을 종료하지 않습니다. 병원 담당자의 인수 확인이 있어야 환자 인계가 완료됩니다.

### 장면 10. 구급활동 기록 검토와 종료

1. 상단 `보고서`를 연다.
2. 다음 8개 검토 카드의 확인 버튼을 모두 누른다.
   - 환자 인적사항
   - 증상·발생시각
   - 환자 평가
   - 구급대원 평가
   - 응급처치
   - 의료지도
   - 이송 의료기관
   - 환자 인계
3. 미상 항목 3건을 각각 `미상으로 확인`한다.
4. `검토 완료`를 누른다.
5. 버튼이 바뀌면 `사건 기록 종료`를 누른다.
6. `인쇄 미리보기`로 구급활동일지 형식의 결과를 확인한다.
7. 상단 `전체 흐름`에서 자동 기록된 타임라인을 확인한다.

발표 마무리 멘트:

> EMS Relay의 핵심은 AI가 의료 판단을 대신하는 것이 아니라, 현장에서 이미 수행되는 확인·문의·회신·인계 과정을 구조화하고 누락과 반복 전달을 줄이는 것입니다. 사람의 확인을 통과한 기록만 공유되고, 미상과 수용 곤란도 그대로 보존됩니다.

## 5. 실제 AWS 연동 테스트

### 준비

- 브라우저 프로필 또는 시크릿 창을 3개 연다.
- 각각 구급대원, 상황실, 병원 Cognito 계정으로 로그인한다.
- 비밀번호는 AWS 콘솔의 Oregon(`us-west-2`) 리전 → Secrets Manager → `ems-relay/demo-users` → `Retrieve secret value`에서 확인한다.
- 비밀번호나 Secret 값을 화면 공유·발표 자료·Git에 노출하지 않는다.

### 역할별 주소

- 구급대원: `https://main.d2edch3bt6kxej.amplifyapp.com/paramedic`
- 상황실: `https://main.d2edch3bt6kxej.amplifyapp.com/control`
- 병원: `https://main.d2edch3bt6kxej.amplifyapp.com/hospital`
- 보고서: `https://main.d2edch3bt6kxej.amplifyapp.com/reports`

### 실연동용 환자 `GW-CARDIO-051`

- 74세 여성
- 가슴 중앙의 조이는 흉통과 호흡곤란
- 흉통 NRS 8, 식은땀과 구역 동반
- AVPU A
- 과거력: 고혈압, 이상지질혈증
- 복용약: 암로디핀
- 환자에게 확인한 약물 알레르기 없음
- 병원 전 판단: 급성관상동맥증후군 의심, 확정 진단 아님

초기 직접 입력값:

- BP `178/96`
- PR `104`
- RR `24`
- SpO₂ `93`
- 체온 `36.5`
- 혈당 `142`
- AVPU `A`

실제 마이크 PTT 1차:

> 환자는 74세 여성입니다. 주호소는 가슴 중앙이 조이는 흉통과 호흡곤란입니다. 흉통은 NRS 8점이고 식은땀과 구역이 동반됩니다. 의식 수준은 AVPU A입니다.

실제 마이크 PTT 2차:

> 증상 시작 시각은 오전 11시 30분으로 환자에게 확인했습니다. 과거력은 고혈압과 이상지질혈증입니다. 복용약은 암로디핀입니다. 환자에게 확인한 약물 알레르기는 없습니다.

실제 마이크 PTT 3차:

> 최초 활력징후는 혈압 178에 96, 맥박 분당 104회, 호흡수 분당 24회, 산소포화도 93퍼센트, 체온 36.5도, 혈당 142입니다. 산소를 비강 캐뉼라로 분당 2리터 투여했습니다. 심전도 감시와 12유도 심전도를 시행했습니다. 12유도 심전도에서 ST 분절 상승이 의심됩니다. 현장 평가는 급성관상동맥증후군 의심이며 확정 진단은 아닙니다.

이송 중 실제 마이크 재평가:

> 이송 중 재평가입니다. 의식 수준은 AVPU A입니다. 혈압 164에 90, 맥박 분당 96회, 호흡수 분당 20회, 산소포화도 97퍼센트, 체온 36.5도, 혈당 142입니다. 흉통은 NRS 8점에서 5점으로 감소했고 호흡곤란은 이전보다 호전됐습니다.

전자 인계와 함께 읽을 구두 인계:

### 검증 순서

1. 구급대원에서 배정 사건을 선택한다.
2. 출동·현장 도착·환자 접촉 버튼을 누른다.
3. 위의 `GW-CARDIO-051` 실제 마이크 PTT 1~3차 대사를 읽는다.
4. 매번 변경안의 경로·값·근거를 검토하고 정확한 항목만 반영한다.
5. 병원 수용 문의를 전송한다.
6. 상황실 화면에 문의 상태가 실시간 반영되는지 확인한다.
7. 병원 화면에서 요청이 나타나는지 확인한다.
8. 병원에서 `추가정보 요청`으로 `12유도 심전도 상세 소견`과 `약물 알레르기`를 요청한다.
9. 구급대원·상황실 화면에 새로고침 없이 반영되는지 확인한다.
10. 구급대원이 `확인값·미상 구분해 회신`하고, 병원이 `수용 가능 회신`을 보낸다.
11. 구급대원이 `이송병원으로 확정` → `이송 시작`을 누른다.
12. 이송 중 재평가를 실제 마이크로 입력하고 최초값과 재평가값이 분리되는지 확인한다.
13. 병원 도착·구두전자 인계·병원 인수 확인까지 진행한다.
14. 보고서에서 확정값, 미상, 병원 회신, 자동 시각이 올바르게 조합되는지 확인한다.

첫 실클라우드 테스트에서는 병원 데모 계정이 특정 기관에 연결되어 있으므로, 수용 곤란 후 다른 병원으로 넘어가는 분기는 사용하지 않는다. 계정에 연결된 기관으로 한 번 문의하고 `추가정보 요청` → `수용 가능`의 성공 경로를 검증한다.

## 6. 합격 기준

- PTT 음성이 화면 중앙에 스트리밍된다.
- Agent 제안은 사람의 선택 전까지 환자 확인값을 변경하지 않는다.
- 숫자·단위·확인 상태가 대사와 일치한다.
- 미상과 진술 기반 정보가 임의의 사실로 확정되지 않는다.
- 재평가가 최초 활력징후를 덮어쓰지 않는다.
- 병원 수용 문의·추가정보 요청·회신·수용 여부가 역할 화면에 실시간 동기화된다.
- 구급대원이 최종 이송병원을 확정한다.
- 병원 인수 확인 전에는 사건이 완료되지 않는다.
- 보고서에 출동부터 인계까지의 버튼 입력 시각과 확인된 임상정보가 반영된다.

## 7. 실패 시 판정 규칙

- 음성 인식이 틀렸지만 HITL에서 거절되어 저장되지 않음: 안전장치 정상, ASR 품질 이슈로 기록한다.
- 틀린 변경안이 사용자 확인 없이 저장됨: 실패.
- 재평가가 최초 활력징후를 덮어씀: 실패.
- 병원 회신이 다른 역할 화면에 반영되지 않음: WebSocket 또는 권한·사건 연결 실패.
- API가 응답하지 않을 때 참고정보가 없다고 명확히 표시됨: 제한 모드 정상.
- API 실패를 수용 가능 또는 임상 사실로 간주함: 실패.
